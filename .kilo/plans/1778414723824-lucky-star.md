# Plan: Coolify Deploy Dokümanı Genişletme

## Hedef
Mevcut `docs/deployguide.md` dosyasını (560 satır, 24 bölüm) genişleterek kapsamlı bir production deploy rehberi haline getirmek. Türkçe, tüm ek bölümler dahil.

## Kaynak Dosyalar
- `docs/deployguide.md` — Ana doküman (genişletilecek)
- `docker-compose.coolify.yaml` — Compose referansı
- `backend/Dockerfile` — Backend container
- `frontend/Dockerfile` — Frontend container
- `frontend/nginx.conf` — Proxy konfigürasyonu
- `coolify.env.example` — Env şablonu
- `backend/sql/schema.sql` — Supabase şema referansı
- `backend/server.py` — FastAPI lifespan ve router yapısı
- `backend/seed_test_user.py` — Seed script referansı
- `docs/INTEGRATION_GUIDE.md` — Entegrasyon detayları

## Mevcut Bölümler (korunacak/güncellenecek)
1-24 arası mevcut bölümler korunacak. Sadece gerekirse ufak düzeltmeler yapılacak.

## Eklenecek Yeni Bölümler

### A. Bölüm 1.5 — ASCII Mimari Diyagramı (Genel Mimari sonrasına)
- İki servisli compose yapısının ASCII diyagramı
- Tarayıcı → Frontend (Nginx) → Backend (FastAPI) akışı
- Backend → Supabase / Neo4j / Elasticsearch bağlantıları
- Internal vs Public network gösterimi

### B. Bölüm 8.5 — Staging vs Production Ortam Ayrımı
- Ayrı Coolify application'lar oluşturma
- Staging env seti örneği
- Production env seti örneği
- Domain naming convention'ları (app.example.com vs staging.example.com)
- Staging'de test user aktif, production'da devre dışı stratejisi
- Farklı Supabase projeleri kullanımı

### C. Bölüm 10.5 — CI/CD Pipeline Entegrasyonu
- Coolify native Git webhook trigger
- Auto-deploy branch bazlı kurulum
- Deploy öncesi otomatik test akışı (pre-deploy hook)
- GitHub Actions ile Coolify API entegrasyonu örneği
- Build cache stratejisi
- Deploy notification (Slack/webhook)

### D. Bölüm 11.5 — Container Kaynak Limitleri
- Backend için önerilen CPU/RAM limitleri
- Frontend (Nginx) için önerilen CPU/RAM limitleri
- Coolify'de resource limit ayarlama
- Memory pressure durumunda davranış
- docker-compose.coolify.yaml'a deploy constraints ekleme örneği

### E. Bölüm 16.5 — Monitoring ve Alerting
- Coolify built-in health check dashboard
- Backend `/api/health` endpoint'inin izlenmesi
- Log aggregation yaklaşımı
- Kritik metrikler: response time, error rate, connection status
- Slack/email notification kurulumu (Coolify native)
- External monitoring opsiyonları (UptimeRobot, etc.)

### F. Bölüm 17.5 — Backup Stratejisi
- Supabase otomatik backup (native)
- Neo4j Aura backup prosedürü
- Elasticsearch snapshot yaklaşımı
- Coolify volume backup
- Environment variable'ların yedeklenmesi
- Disaster recovery senaryosu ve RTO/RPO hedefleri

### G. Bölüm 18.5 — Scaling ve Performans
- Horizontal scaling stratejisi (backend replicas)
- Nginx rate limiting konfigürasyonu
- Connection pooling (Supabase, Neo4j, Elasticsearch)
- Static asset caching (Nginx)
- Coolify load balancer entegrasyonu
- Replicas ile session affinity konusu

### H. Bölüm 22.5 — Güvenlik Hardening
- CORS_ORIGINS = * yasağı
- Secret yönetimi en iyi pratikler
- Nginx security headers (X-Frame-Options, CSP, HSTS)
- Backend rate limiting
- Docker image security scanning
- Coolify network isolation
- Supabase RLS kuralları
- SSL/TLS sertifikası yenileme otomasyonu

### I. Bölüm 18'in yerine — Troubleshooting Karar Ağacı
- Akış şeması formatında karar ağacı
- "Frontend açılıyor mu?" → Hayır/Evet dallanma
- "API çalışıyor mu?" → HTTP status kodlarına göre dallanma
- "Veritabanı bağlantısı var mı?" → Servis bazlı kontroller
- Her yaprak node'da çözüm adımları

### J. Bölüm 24.5 — Hızlı Referans Kartı (Sonuç sonrasına)
- Tek sayfalık komut reference card
- Tüm endpoint'lerin listesi
- Tüm env variable'ların özet tablosu
- Sık kullanılan docker/coolify komutları
- Log okuma hızlı rehberi
